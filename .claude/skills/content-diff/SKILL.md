# Content Differentiation — 멀티사이트 SEO

같은 키워드("대전세븐나이트")를 노린 2~5개 사이트를 운영할 때, 콘텐츠가 비슷하면 **구글·네이버가 중복으로 판단해서 둘 다 깎임**. 차별화 필수.

## 차별화 매트릭스 (10 차원)

콘텐츠를 만들 때 다음 10개 차원 중 **최소 6개를 다르게** 해야 자연스러움. 매장명·전화처럼 고정인 변수는 그대로.

| 차원 | 1번 사이트 (예) | 2번 사이트 (차별화 예) |
|---|---|---|
| **도메인** | seven-97b.pages.dev | seven1-2jn.pages.dev |
| **W.T 닉네임** | 원숭이 | 원숭이 (필수 고정인 경우 다른 차원에서 차별화 강화) |
| **톤** | 정보·예약형 ("전화 한 통이면 끝") | 후기·증명형 ("247건 후기, 평균 매칭 3분") |
| **H1** | "4인1조 W.T 즉시 부킹" | "둔산동 직접 가본 사람만 아는 곳" |
| **메타 타이틀** | "테이블예약·부킹" 키워드 강조 | "실시간 자리 안내" + 사회적 증거 |
| **사회적 증거** | 없음 또는 약함 | 평점 4.9/247건/매칭 3분 명시 |
| **FAQ 질문** | 일반형 ("예약 어떻게?") | 구체 시나리오형 ("여자 2명 합석?", "토요일 늦게?") |
| **섹션 구성** | hero/why/how/info/faq/last-cta | + reviews 섹션 추가, "왜 1순위?" 헤더 변형 |
| **후기 섹션** | 없음 | 3건 후기 블록 (지역별 페르소나) |
| **컬러 테마** | 다크+골드+핑크 | 다크 그린+에메랄드+시안 |
| **OG 이미지 톤** | 정보형 (전화·매장명 강조) | 증명형 (후기 수 강조) |
| **JSON-LD 추가 schema** | NightClub+Person+FAQ | + AggregateRating + Review (1번에 없으면) |

## 차별화 권장 순서 (가장 강한 신호 순)

1. **본문 텍스트 70%+ 다르게** (가장 결정적)
   - H1·H2·hero·CTA 카피 모두 다른 표현
   - FAQ 질문·답변 70% 다르게
   - 후기 섹션 추가/제거
2. **메타 태그** (검색결과 클릭률 분리)
   - title·description 다른 의도·톤
   - keywords 부분 겹쳐도 OK (핵심 키워드 동일 필요)
3. **JSON-LD `name`/`description`** 다른 표현 (NightClub.alternateName은 둘 다 동일 OK)
4. **OG 이미지** 다른 디자인·다른 카피
5. **컬러 테마** (가장 약한 신호지만 봇·사람 모두 인식)

## 콘텐츠 차별화 템플릿

### 톤 변형 매트릭스
| 톤 | 키워드 | 예시 카피 |
|---|---|---|
| 정보·예약형 | "예약", "안내", "직통" | "전화 한 통이면 끝" |
| 후기·증명형 | "후기", "평점", "건수" | "247건 누적 후기" |
| 가격·할인형 | "최저가", "할인", "프로모션" | "같은 조건 대전 최저가 보장" |
| 외지·접근성 | "세종", "청주", "교통" | "세종에서 30분, 자리 책임 보장" |
| 시간·즉시형 | "지금", "오늘", "당일" | "30분 후 출발해도 자리 OK" |
| 인물·신뢰형 | "7년", "단골", "추천" | "둔산동 풀타임 7년 W.T" |

각 사이트에 **다른 1~2개 톤** 배정.

### FAQ 차별화 풀

**일반형 7개:**
1. 예약 어떻게 하나요?
2. 4인1조가 뭔가요?
3. 주대 가격은?
4. 예약 없이 가도 되나요?
5. 부킹률 좋은가요?
6. 여자 손님 환영하나요?
7. 영업시간은?

**시나리오형 7개 (1번에 없으면 2번에):**
1. 여자 2명인데 합석 들어갈 수 있나요?
2. 토요일 늦은 시간에 자리 잡을 수 있나요?
3. 처음 가는데 어떻게 진행되나요?
4. VIP 룸·스테이지 가까운 자리도 가능한가요?
5. 외지에서 오는데 매칭 잘 되나요?
6. 예약하면 더 비싼가요?
7. 노쇼하면 페널티 있나요?

**비교·결정형 7개 (3번 사이트용):**
1. 옆 매장이랑 뭐가 달라요?
2. 같은 가격이면 왜 여기?
3. 단골이 자주 오는 이유는?
4. 어떤 손님이 잘 맞아요?
5. 비추천하는 경우는?
6. 첫 방문 vs 재방문 차이는?
7. 결제 방법은?

## 중복 검사 자동화

### A. JSON-LD 본문 일치 검사
```bash
# 두 사이트의 JSON-LD 추출
curl -s https://seven-97b.pages.dev/ | grep -oP 'application/ld\+json"\>\K[^<]+' > /tmp/site1-jsonld.json
curl -s https://seven1-2jn.pages.dev/ | grep -oP 'application/ld\+json"\>\K[^<]+' > /tmp/site2-jsonld.json
diff <(jq -S . /tmp/site1-jsonld.json) <(jq -S . /tmp/site2-jsonld.json) | head -50
```

### B. 본문 단어 겹침률
```bash
curl -s https://seven-97b.pages.dev/ | grep -oP '<h[12]>[^<]+' | sort > /tmp/site1-headings
curl -s https://seven1-2jn.pages.dev/ | grep -oP '<h[12]>[^<]+' | sort > /tmp/site2-headings
comm -12 /tmp/site1-headings /tmp/site2-headings | wc -l
# 결과: 겹치는 헤딩 수 / 5 미만이어야 함
```

## 🚦 자동 실행 흐름 (새 위성 사이트 생성 시)

1. **고정값 확인** (매장·전화 등 바뀌면 안 되는 것)
2. **차별화 매트릭스 표 작성** (1번 사이트와 비교)
3. **톤 결정** (위 풀에서 1~2개 선택)
4. **FAQ 7개 선택** (1번 사이트와 80%+ 다른 질문)
5. **후기 섹션 추가/제거 결정**
6. **컬러 테마 선택** (1번과 다른 팔레트)
7. **OG 이미지 새로 디자인** (`og-image` 스킬)
8. **JSON-LD `name`/`description` 다른 표현으로**
9. **본문 작성 후 중복 검사** (위 자동화)
10. push → 배포 → 인덱싱 별도 대기

## 🧠 함정

- **고정값(매장명/전화)은 그대로 OK** — 한 사람이 여러 사이트 운영하는 건 자연스러움. 페널티 X
- **JSON-LD 완전히 같으면 안 됨** — 최소 `name`, `description`, `aggregateRating` 다르게
- **OG 이미지 같은 파일 재사용 X** — 도메인이 다르면 다른 OG여야 함
- **사이트맵의 image:title도 차별화** — `<image:title>` 다른 표현으로
- **다른 색감인데 같은 카피** → 사람은 속아도 봇은 본문 텍스트로 매치, 페널티 가능
- **짧은 페이지(500자 미만) 다중 운영** → 둘 다 thin content 페널티. 1500자+ 권장
